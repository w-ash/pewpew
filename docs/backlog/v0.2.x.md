# v0.2.x — Phase 1: host engine core

First end-to-end light on real LEDs (`research/synthesis/architecture.md` §11
Phase 1). A pure render core with the ADR-005 authoring contract, the §8 dev
loop (preview sink → hot reload → golden frames), one paced clock (ADR-010),
and DDP 8-bit out to a stock WLED node (ADR-003/004). Everything later builds
on this; nothing here is throwaway.

**Gates: cleared.** The three v0.1.x Phase-0 gates all have desktop verdicts
(item 1 PASS at 52×, 2026-07-15; item 2 GO, 2026-07-16; item 13 PASS,
2026-07-27). Each still wants a rerun on whatever host gets deployed —
tracked in v0.1.x, blocking nothing here.

**State (2026-09-03).** v0.2.0 (engine core, contract frozen as amended,
five study patterns bit-identical), v0.2.1 (paced clock, sinks, the
`python -m pewpew run` no-hardware dev path, playground retirement), v0.2.2
(typed params, enforced ranges, param-liveness) and v0.2.3 (live param
sliders on the preview page, per-pattern default `--map`) have landed —
completed stories below carry the details. The dead-`spin` parameter that
motivated v0.2.2 is now caught by the L1 suite at rms 2.65e-08 against a
1e-3 bar, and by a second live-set check that turns each knob mid-sequence.
The dev loop is now interactive end to end: edit nothing, open the preview,
pull a lever and the engine answers. v0.2.4 (2026-09-03) closed the loop the
other way: `run` takes any file, and a save swaps the new class in between two
frames with `t`, params, buffers, the RNG stream and scalar state all kept —
proven bit-identical to an unswapped `render_sequence` for all five gallery
patterns. Those two stories were added 2026-08-23 after a composability
review, along with layer compositing (v0.2.6), which §2 designs but no ADR,
phase, or story covered. **Next: v0.2.5 DDP to stock WLED once the hardware
(ordered 2026-08-22) arrives, else v0.2.6.** Landing hot reload arms the last
of ADR-010's three GC-retest triggers; the retest is its own story below.

#### Authoring surface

Shared context: ADR-005 (Accepted 2026-07-26) is the contract —
`before_render(dt, features)` + `render(x, y, z, index)` over normalized 0–1
coordinate **arrays**, persistent `self.pixels`, time-parameterized motion,
per-frame exception containment. `bench/authoring/surface.py` is the
throwaway prototype of it; the five patterns in `bench/authoring/` are the
acceptance corpus — they must port to the real engine with their behavior
unchanged. Stumble numbers refer to `bench/results/authoring-2026-07-16.md`.

- [x] **Pure render core + pattern contract**
    - Effort: L
    - What: `render(t, mapping, params, seed) → frame` as a pure function, with the ADR-005 pattern base class, normalized world coordinates, persistent frame buffer, and per-frame exception containment.
    - Why: Every other story in this series and every later phase sits on it; purity is what makes golden frames, deterministic scrubbing, and the fleet twin possible (§8, T-1).
    - Dependencies: v0.1.x §12 items 1–2
    - Status: Completed (2026-07-27)
    - Notes: `src/pewpew/{pattern,kit,render,mapping,features}.py`; supersedes `bench/authoring/surface.py`. All five patterns ported to `src/pewpew/patterns/` and proven **bit-identical** (`np.array_equal`, not RMS-tolerant) against the prototype over the study's own 120 frames at seed 42 — `tests/test_port_equivalence.py`. Purity lands at the *sequence* level, not the frame level: ADR-005 patterns are deliberately stateful, so `render_sequence(factory, mapping, params, seed, frames, fps)` is the pure function §8 means, and `Renderer.advance_to(t)`/`.step(dt)` is the live form the paced clock will drive. Timestamps accumulate `t += 1.0/fps` to match `FakeClock` bit-for-bit without importing it (engine must not depend on the harness). `src/harness/` untouched. Also landed: the `time()` module-global hack is gone (frame-scoped `ContextVar`), and a `params` key naming an undeclared `Param` now raises rather than creating a dead knob.

- [x] **Idiom-kit additions mandated by the §12 item-2 verdict**
    - Effort: M
    - What: Add `fade(dt, tau)`, `bins(x, n)`, `sample2d(field, x, y)`, and `hash01(x, salt)` to the standard idiom kit alongside the ADR-005 built-ins (`time()`, `wave()`, `triangle()`, `square()`).
    - Why: The authoring-surface GO was *conditional* on these four — they shield the stumbles the study measured (threshold/dtype edges, frame-rate-dependent decay, per-pixel hashing).
    - Dependencies: Pure render core
    - Status: Completed (2026-07-27)
    - Notes: In `src/pewpew/kit.py`, each a bit-exact substitute for the study expression it replaces, with `tests/test_kit.py` asserting that against the inlined original. Shipped as `hash01(x, seed, salt)` — **seed and salt stay two arguments, deliberately**: the study's `12.9898*x64 + self.seed + salt` associates left-to-right, and a pre-summed salt diverges by 1 ulp on 46 of the study's 120 frames. That is stumble #6's own failure mode one step upstream, so the signature reproduces the study by construction rather than by luck. `fade` is dt-based per Q-5. Adopted at every call site except fire's `lift`, which is `exp(-dt*rise)`, not `exp(-dt/tau)`.

- [x] **Authoring docs for the three measured friction points**
    - Effort: S
    - What: Document the internal-field idiom, that `np.where` evaluates both branches (so guards must be safe, not lazy), and where RNG belongs so patterns stay seed-reproducible.
    - Why: 13 of the study's 17 stumbles were expertise-shielded — an author without NumPy fluency hits them. Docs are the cheapest mitigation the study identified.
    - Dependencies: Idiom-kit additions
    - Status: Completed (2026-07-27)
    - Notes: `docs/authoring.md`. Covers the mandated three (#12/#15, #5, #14) plus the three the study's own "Reading of the evidence" clusters with them: private per-pixel state (#17), dt-decay (#2), and threshold/dtype edges (#6, #9). Every claim cites its `# STUMBLE-N` anchor in `bench/authoring/*.py`, and every example was executed against the real engine rather than written from the docstrings.

- [x] **Decide and implement private per-pixel state buffers (stumble #17)**
    - Effort: M
    - What: Decide whether patterns may declare private per-pixel arrays alongside the sanctioned `self.pixels`, and implement the outcome (including lifecycle across hot reload).
    - Why: The study left this open; fire and any particle pattern need per-pixel state beyond the output buffer, so leaving it undecided blocks a faithful port.
    - Dependencies: Pure render core
    - Status: Completed (2026-07-27)
    - Notes: **Decided yes**, recorded as `## Amendment (2026-07-27)` in ADR-005 with architecture §3 following it. A `setup(n, x, y, z, index)` hook hands the pattern its coordinates once per binding; `self.buffer(name, shape)` declared there is engine-managed (zeroed on rebind, reallocated on mapping change, read-only inside `render`). **Coords-at-setup is the actual unlock** — #17's bind was that `before_render` never sees coordinates. Precedent converged across three lineages: ISF's manifest-declared host-allocated `PERSISTENT` buffers [S218], Shadertoy's previous-state/next-state buffers [S219], and Pixelblaze's persistent arrays [S680] — the last of which pays for them with an *impure render*, the trade we explicitly reject. Registry keys on name+spec, never array identity, because authors rebind (fire does). Two follow-ons this leaves open, both for the hot-reload story: `setup()` failures are deliberately *not* contained (they propagate out of `Renderer.__init__`, so the reload supervisor must keep the last-good binding itself), and scalar per-pattern state (`self.phase`, `self.head`) is not engine-tracked, so reload must decide whether it carries. Also worth a later pass: comet's sparkle still uses the study's time-salted workaround rather than a private buffer, since "behavior unchanged" was the port's acceptance bar — so the corpus does not yet exercise the feature #17 motivated (`docs/authoring.md` §2 demonstrates it instead). Unblocks "Port the upgraded fire to Python" in `unscheduled.md`.

- [x] **Typed params (§5) + param-liveness check in the L1 harness**
    - Effort: M
    - What: Typed `Param` declarations per §5/ADR-006, plus a harness check that wiggles each declared param across its range and asserts the frame sequence actually changes.
    - Why: The sdf3d `spin` parameter was a mathematical no-op and *nothing* caught it — not the authoring surface, not golden frames, because other motion masked it.
    - Dependencies: Pure render core
    - Status: Completed (2026-08-22)
    - Notes: `Param` now validates its own declaration (`lo < hi`, default in range), learns its `name`/`owner` via `__set_name__`, and derives `step`/`decimals`; `declared_params(cls)` reads declarations back off the class and `ParamSet` holds them alongside current values (`src/pewpew/pattern.py`, exported from `pewpew`). Governing record is `## Amendment (2026-08-22)` in ADR-006 — status stays *Proposed*, since Phase 1 lands only the declaration half and the canonical tree (paths, partial-merge, presets, `save`, mDNS) is Phase 3. The Phase-1 object is deliberately a **`ParamSet`, not a tree**: no paths, no nesting, and it must not pre-spend the vocabulary the tree will need. **Range decision: refuse, not clamp** — a clamp renders one value while every surface displays another, which is the dead-knob failure one layer up; float noise at an endpoint snaps (a slider stepping `lo + i*step` can land an ulp past `hi`), anything further out is refused. Refusals split into `reason` (network-safe) and `hint` (names the source file), because the preview server is unauthenticated by design and a refusal must not serve the layout of the disk. **The correction that mattered most**: the first plan resolved params per frame in `advance_to`, justified as preventing a tear between `before_render` and `render` (plasma reads `speed` in one, `scale` in the other). Wrong — `pace.py:130-137` drains `call_soon` at the top of the tick, *before* `advance_to`, so the tear is already impossible; and ADR-006's real per-frame seat must evaluate LFOs *at t*, which needs `t` and the feature frame, neither of which `apply(pattern)` has. Building it would have been the wrong signature for the right reason. Values resolve at bind and **the frame path is untouched**. **Second correction, a live crash path**: `call_soon` propagates a closure's exception out of `run()` (`pace.py:110-112`), so a raising `set_param` reached from the websocket would let a browser stop the show with one out-of-range slider — verified, `run()` dies with the ValueError. Hence `ParamSet.check()`: non-raising, and the single source of every refusal wording so a socket reply and `set`'s exception can never diverge. The check is `tests/test_param_liveness.py` — nine cases, one per (pattern, knob), self-extending as patterns gain knobs, endpoints rather than a nudge so the declared range is under test too. Acceptance measured both ways: with the xfail removed `sdf3d.spin` fails at **rms 2.65e-08** (not 0 — `angle` still accumulates into cos/sin, it just cannot move a y-axis-invariant SDF), and a freshly-added unread `Param` on geq fails at exactly 0.0. Bar is `LIVENESS_RMS = 1e-3` in `harness/goldens.py`, now shared with `test_golden_frames.py::test_seed_changes_output`, which had the same literal inline. **sdf3d stays frozen** — `test_port_equivalence.py` holds it bit-identical to the study prototype, so fixing the axis would break the evidence chain to repair the very bug that proves the check works; `xfail(strict=True)` means the exemption fails as XPASS if `spin` ever comes alive. Also landed: `Renderer.params` is the set (identity stable across `rebind`, since v0.2.3 holds a reference to it), `Renderer.set_param`, CLI validation moved *ahead* of `Renderer(...)` so a knob typo exits with one clean line while a bad mapping or a raising `setup` still gives a full traceback (binding is deliberately loud, `render.py:152-156` — a blanket `except ValueError` would have quietened it), and one canonical `STUDY_CASES` table in `pewpew.patterns` replacing the (class, mapping) triple three test files each re-derived by hand. Semantic change worth knowing: a `Param` declaration now beats an `__init__` assignment to the same name — the prototype's isinstance guard let `__init__` win — no corpus pattern does it, so bit-exactness holds. **Rejected with numbers**: a descriptor `Param` is the idiomatic 2026 answer and would type `self.speed` as `float`, but measured 4.15 ns plain / 7.4 ns for the current shape / 25–35 ns data descriptor, and the repo runs no mypy, pyright, CI or lint — zero benefit today; revisit when a type checker lands. **Two things v0.2.3 should not rediscover**: `SinkDriver` is *not* reusable for param coalescing (its newest-wins mailbox is one slot, so a `scale` set would discard a pending `speed` set — param coalescing is last-write-wins *per key*), and no rate limiting is needed (a drag fires 60–120 events/s against a 60 Hz drain, ~2 closures per tick); `describe()` is the hello payload, a list so display order survives transport. Left open: a live set only reaches a pattern that reads the knob per frame, so one precomputing from a knob in `setup` would ignore it — that wants a live-set liveness check when a pattern makes it real. This **arms** the second of ADR-010's three GC-retest triggers; the retest is a measurement, due once hot reload lands too.

#### Frame pipeline & sinks

Shared context: §8 gives the leverage order — render core + preview sink
first, hot reload second, browser preview third, golden frames from day one.
The preview fixes already landed carry one hard-won requirement forward: any
preview sink must apply display gamma, or low-end glow crushes to black.

- [x] **Paced render clock, deadline-corrected (ADR-010)**
    - Effort: M
    - What: One paced clock measuring elapsed, sleeping the remainder, and correcting accumulated error; per-sink newest-wins backpressure bounded at ~2 frames in flight.
    - Why: ADR-010's core mechanism; the single clock is also where modulated params and audio features resolve exactly once per frame.
    - Dependencies: Pure render core
    - Status: Completed (2026-08-20)
    - Notes: `src/pewpew/pace.py` — `PacedLoop` is the bench `deadline` pacer ported exactly (absolute schedule seeded once, skip-ahead with the no-`+1` rule and its rationale comment carried over), plus the spin variant as a `spin_margin` option with `measure_spin_margin()` for the host probe; the engine never auto-probes. The open timestamp question got decided and recorded as `## Amendment (2026-08-20)` in ADR-010: **engine time is nominal schedule time, never measured wall time** — `t += 1/fps` per tick by repeated addition, one further period per skipped slot — so a live show is bit-identical to `render_sequence` at the same slot (`tests/test_pace.py::test_engine_time_matches_render_sequence_bitwise`, `np.array_equal`). Working the skip arithmetic through fixed two wrong intuitions worth keeping: a 2.5-period stall drops exactly *one* slot (the next frame renders immediately, late in the last past slot, rather than idling), and a sub-2-period stall drops *zero* — both are what the no-`+1` rule buys. Backpressure ships as `SinkDriver` (per-sink worker + 1-slot mailbox = Fadecandy's 2-in-flight bound); `PacedLoop` itself takes plain `on_frame(t, frame)` callables handed one shared read-only copy per tick, so the Sink protocol stays owned by the sink story, which wraps its `send` in a `SinkDriver`. Seams left deliberately: `call_soon(fn)` is the loop-thread mutation point hot reload will use, and a callback exception (including an uncaught bind failure) propagates out of `run()` — the reload supervisor owns catching it. Features already resolve once per frame inside `advance_to`; the param tree will hook the same place (typed-params story). GC posture: one frame copy + one tuple per tick, no growing containers — the ADR-010 GC retest obligation (re-bench once sinks + param tree + hot reload exist) stands unchanged.

    - Why: The no-hardware dev path — §8 makes preview-as-a-sink the first thing after the render core, and it costs ~nothing beside DDP.
    - Dependencies: Pure render core
    - Status: Completed (2026-08-20)

Runner: `python -m pewpew run <pattern> [--map] [--ansi] [--preview]` — minimal, hot reload extends it. Both sinks take a `status` supplier; the runner wires `renderer.error` into it (red line / banner beside the pulsing-red frame) — the same seam hot reload's supervisor will use. Verified live: 120 frames @ 60 fps with both sinks, 0 skips; break-and-heal surfaces and clears in both. three.js `Points` for 3D deferred to Phase 3 (z-slice 2D layout instead, matching ANSI). **Landing sinks is one of ADR-010's three GC-retest triggers** (with param tree + hot reload) — the soak obligation stands. Review pass 2026-08-21 closed seven findings, four of them on the runner rather than the sinks: the `status` supplier read `renderer.error` twice (a pattern healing between the two reads painted the string `None` in red), the CLI configured no log handler at all — so the preview URL was invisible *and* `Renderer._contain`'s traceback went to stderr straight through the ANSI rewind block, desyncing it permanently — the status line's row was not reserved in the height budget, and `SinkDriver.stop()`'s "transport still in use" bool was discarded by its only caller. The runner now owns log presentation (`_DeferredLog` holds records while `AnsiSink.interactive` is true, replaying on exit; the sink's red status line stays the in-band channel), sniffs the terminal size itself (`AnsiLayout` keeps its 80x24 defaults so `render_frame` stays pure and the golden stays valid), and takes a `now`/`sleep` seam like every other paced component. `SinkDriver` gained `drain()` — `stop()` discards the pending frame by design, so `--frames N` was reliably losing frame N. Left deliberately unchanged: `_axis_res` sizes by distinct-value count while `bins()` positions over [0, 1], so a mapping spanning only part of the unit range under-fills the grid. The browser preview's `makeLayout` makes the same assumption, and that shared assumption is what makes the two previews agree — normalizing one alone would split them. Documented on `from_mapping`; the fix for both is a story in `unscheduled.md` under imported maps.

    - Effort: M
    - What: Sliders on the served preview page, one per declared `Param`, that set the running pattern's parameter values over the existing websocket while the show plays.
    - Why: The retired playground's best feature was knob-turning, but its sliders drove JS imitations; these drive the real engine, so what a knob shows is true (the dead-`spin` lesson). Restores the interactive half of the dev loop until Phase 3's full control plane.

    - Notes: `Controls` is a two-method Protocol in `sinks/base.py` (`describe()`, `set(name, value) -> reason | None`), so `PreviewSink` imports neither `Renderer` nor `PacedLoop`; the runner's `_LoopControls` is the bridge. Wire protocol grew three shapes, all recorded in the `preview.py` module docstring: hello carries `params` (`ParamSet.describe()`, or `[]` when nothing is wired), `{"type":"set"}` is the only inbound message, `{"type":"refused"}` goes back to whoever asked, and `{"type":"params"}` goes to everyone. **The refusal carries `check`'s reason and never `hint`** — the hint names a source file and this port is unauthenticated by design — and `test_refused_set_names_the_range_but_never_a_source_path` asserts exactly that rather than trusting it. The sink writes no validation of its own: bools, non-numbers and non-finite values all arrive from `json.loads` and are `check`'s job, which keeps one wording for a refusal whether it came from a socket or the CLI. **The echo is recomposed per frame, not pushed when a set is accepted** — the first design pushed at accept time and would have shipped stale values, because a set is *queued* onto the loop thread and has not landed yet when `controls.set` returns. Rebuilding from `describe()` in `send` costs a measured 2.0 us on a SinkDriver worker, never touches the render loop, and is unconditionally true; clients see it only on a change, via the same current-state-not-delta trick that already makes `status` immune to newest-wins coalescing. No lock was needed for the handler thread's refusal reply racing a driver worker's frame: `websockets.sync`'s `Connection.send` serializes unfragmented sends on `protocol_mutex` (checked in `send_context`, not assumed). Both v0.2.2 warnings were honored — no `SinkDriver` for coalescing, no rate limiting. **A latent flake this surfaced and fixed**: `start()` returns as soon as the server thread is spawned, so a fast `stop()` closed the listener before `serve_forever` finished starting and it raised EBADF from its own opening log line. Harmless but noisy, and it went from 0-in-5 runs to ~25% once the six new socket tests changed the timing; `_serve` now tolerates an OSError while `_stopping` is set and nothing else. Verified 0 in 200 back-to-back start/stops. On the page: the lever row reuses the retired playground's CSS, a slider under the pointer is exempt from echoes so an update cannot fight a drag, and a refusal borrows the status bar for 4 s and hands it back rather than erasing a renderer error that is still true. **The screenshot caught what the statistics could not**: `#meta` was `position: fixed` at the viewport bottom, which is where the lever row now lives, so the readout overprinted the first slider — the footer is one flex row in flow now. Visual verification per `.claude/rules/preview-visual-verify.md` did both halves: glow bands stayed spread (low 48676 / mid 322548 / high 163951, so the b68b96a gamma is intact), `speed=0` froze the canvas to a bit-identical digest a second apart and `speed=2` moved it again (the unambiguous proof a slider reaches the engine), four `scale` values gave four distinct frozen digests, and a second tab followed the first. One metric that did *not* work, worth not repeating: band-crossing count along a scanline fell as `scale` rose, because 300 pixels alias badly past Nyquist — the frozen-digest comparison is the honest measure. Also landed: `test_param_liveness.py` gained the **live-set** check ADR-006 left open ("a live-set liveness check is the answer when a pattern makes it real"), which the bind-time check cannot see — proven with teeth against a throwaway pattern reading its knob only in `setup`, which passes the bind-time bar at rms 0.37 and fails the live one at exactly 0. The wiring points already exist on both ends: `PreviewSink._handler` currently drains client messages and ignores them — that loop becomes the back-channel — and `PacedLoop.call_soon(fn)` is the sanctioned loop-thread mutation seam, so a param set is a small closure queued there, never a cross-thread poke at the renderer. Hello already carries the pattern metadata channel; extend it with the `Param` declarations (default/lo/hi/label — the retired playground built its lever row from exactly this shape, `preview/index.html@519eb6d:695`). Multiple tabs: last-write-wins, and echo accepted sets back out as a status-style message so other tabs' sliders follow. Scope fence: this is a dev-loop nicety, NOT the Phase-3 control plane — no presets, no HTTP tree, no OSC/MIDI; Phase 3 absorbs or replaces it. `--param` stays the launch-time path and the ANSI sink stays view-only.

    - Notes: `src/pewpew/reload.py` (`Reloader`) over a new `Renderer.swap(pattern)` primitive (`render.py`), with `ParamSet.inherit`/`redeclare` (`pattern.py`). Leaf-module re-import as §8 asks: each load execs a **fresh module object under a stable `sys.modules` key** (`pewpew_user.<stem>`), never `importlib.reload`, which re-execs into the same object so a renamed class leaves both names behind and, for a gallery file, would rebind `pewpew.patterns.comet.Comet` under `STUDY_CASES`. `swap` has a **strong exception guarantee**: the candidate binds against the inherited param values *before* anything on the renderer changes, so a raising `setup` propagates (bind stays loud, `render.py`) with the old pattern untouched — that settles open point (1). Open point (2) settled by user decision: plain scalar state (`self.head`, `self.phase`) is kept when the new instance has the same name at the same exact type after its own `__init__` (bool/int/float/str only; author-managed arrays start fresh — ADR-005's answer is `self.buffer`), and a name declared as a `Param` on either class is never treated as a scalar, so a knob demoted to a constant takes the author's new constant. Inheritance is a lifecycle hook, not an after-the-fact copy: `Inheritance(old)` (`pattern.py`) is handed to `_bind`, applies `__init__` scalars and the RNG state *before* `setup` (so what `setup` assigns is the new code's own), and each `self.buffer(...)` declaration takes over the old array when name and full `BufferSpec` match (`pixels` included), so a view `setup` derives from a buffer refers to the kept data. Buffers are **copied**, one O(N) per reload: a candidate whose `setup` scribbles on a buffer and then raises has touched nothing the old pattern owns, which is what keeps the strong guarantee honest. A shape or dtype change gets the fresh zeroed buffer. Numbers are one inheritance family (`self.phase = 0` that became a float is kept). Params follow ADR-006 §"Reload policy": kept when they still fit, else reset to the *new default*; the `ParamSet` keeps its identity (the preview's `_LoopControls` holds it) and now stores one `(declarations, values, name)` tuple swapped in a single attribute store, because `describe()` iterating one dict and indexing the other across a redeclare would `KeyError` on a sink worker. Open point (3): confirmed — `error` is left alone by the swap and clears on the next healthy frame; the once-per-site log guard *is* reset, since its keys include file and line, which an edit usually preserves. **The star test** (`tests/test_reload.py`): a swap mid-sequence, to a fresh instance and to a class re-executed from the same file, renders `np.array_equal` to an unswapped `render_sequence` for all five gallery patterns — that is what proves the kept set is complete. `watchfiles` 1.2.0 is the third runtime dependency (sanctioned by §9 and ADR-020 line 42; no new ADR), imported lazily so the suite never loads it; it watches the **parent directory** non-recursively with an exact-path filter, because an editor's atomic save replaces the inode and a file watch goes silent on inotify; `debounce=100` (the 1600 ms default is tuned for restarting servers) with the source digest making duplicate fires free. `reload()` runs on the loop thread via `call_soon` and never raises; a failure sets `Reloader.error`, path-free by construction (`SyntaxError` reformatted as `msg (line N)`), which the runner's status supplier now reads *ahead of* `renderer.error` — if the old pattern is broken and the fix has a syntax error, the syntax error is the answer. The preview gained a `declare` message (value-free declarations, deduped per client on that text, followed by a forced `params` echo) so a reload that adds a knob grows a slider on the open page. A review pass the same day (10 findings, 9 probed) closed: stale-bytecode reloads, `setup`-assigned scalars and views lost to after-the-fact copying, dtype ignored on buffer match, int-literal scalars resetting, a gone-then-restored file leaving the banner stuck, a `FileNotFoundError` path reaching the socket in the read-then-load race (gone by construction now that one read feeds the exec), `BaseException` swallowing Ctrl-C, gallery reloads polluting `sys.path`, and `name:Class --patterns` falling through to the gallery. Verified live with the real watcher and a headless browser: an edit adding a `Param` and changing the colour swapped at t=66.7 with `pixels` and `head` kept and the new slider present; a syntax error showed the banner with the line and no path while the old pattern kept rendering; restoring the file cleared it; touching `src/pewpew/patterns/comet.py` under a gallery run reloaded it. Left deliberately: only the entry file is watched (a sibling module or the engine needs a restart); exec and swap hitch one frame, which the paced loop's skip logic absorbs; a kept value is not re-read from an edited default (reset on the preview, or rename the attribute). This lands the last of ADR-010's three GC-retest triggers; the retest is the story below.

    - Effort: S
    - What: Let `python -m pewpew run` resolve a pattern from a path or a search directory, not only from the built-in gallery — `_pattern_class` (`src/pewpew/__main__.py:45`) mapped names against `pewpew.patterns.__all__` and nothing else.

    - Dependencies: none
    - Status: Completed (2026-09-03)
    - Notes: `src/pewpew/load.py` — `resolve(spec, search_dir)` → `LoadedPattern(cls, source, attr, module_name, digest)`. Resolution order as proposed: an explicit path (`x.py`, `dir/x.py`, or `x.py:ClassName`), then `--patterns DIR/<name>.py`, then the gallery by lowercased name. **No implicit working-directory search**: `run comet` is always the gallery, so a stray `comet.py` beside the shell cannot shadow it (tested). A file must define exactly one `Pattern` subclass *of its own* (`__module__` check, so a base imported from a sibling is not a candidate); several → `LoadError` listing them and asking for `:ClassName`. A user file's directory goes on `sys.path` for script-style sibling imports (a process-global side effect, documented; skipped for files inside the pewpew package so a gallery reload never puts `src/pewpew/patterns/` ahead of installed packages). `Source.read(path).load(...)` compiles **the bytes in hand** into a fresh module under a stable `sys.modules` key (never the import system's bytecode cache, whose mtime-and-size check cannot tell two same-length saves in one second apart, and which would drop a `__pycache__` beside the author's file) — the shape hot reload needed, decided here so that story did not refactor this one — and `digest` (SHA-256 of the bytes) is what a reload later compares. - [ ] **Layer compositing — combine N patterns into one frame**
    - Effort: L

    - Notes: Surfaced 2026-08-23 by a composability review. **Two tree defects to fix in the same pass.** (1) §2 stage 2 states a decision — alpha-over/additive in linear space, layers as canvases over point subsets (LedFx virtuals [S305], projectMM layers [S715:docs/architecture.md#L285-L318]), crossfade blending two frames and never two engines (avoiding WLED's copy-the-whole-Segment transition [S645:wled00/FX_fcn.cpp#L1330-L1367]) — with **no ADR**, while stage 1 links ADR-005 and stages 4/6 link ADR-001/ADR-002. `CLAUDE.md` says architecture.md holds no decision without an ADR, so this is out of conformance; the three sources above are already in the tree and are the evidence base.
