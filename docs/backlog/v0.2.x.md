First end-to-end light on real LEDs (`research/synthesis/architecture.md` §11
Phase 1). A pure render core with the ADR-005 authoring contract, the §8 dev
loop (preview sink → hot reload → golden frames), one paced clock (ADR-010),
and DDP 8-bit out to a stock WLED node (ADR-003/004). Everything later builds
on this; nothing here is throwaway.

**Gates: cleared.** The three v0.1.x Phase-0 gates all have desktop verdicts
(item 1 PASS at 52×, 2026-07-15; item 2 GO, 2026-07-16; item 13 PASS,
2026-07-27). Each still wants a rerun on whatever host gets deployed —
tracked in v0.1.x, blocking nothing here.

#### Authoring surface

Shared context: ADR-005 (Accepted 2026-07-26) is the contract —
`before_render(dt, features)` + `render(x, y, z, index)` over normalized 0–1
coordinate **arrays**, persistent `self.pixels`, time-parameterized motion,
per-frame exception containment. `bench/authoring/surface.py` is the
throwaway prototype of it; the five patterns in `bench/authoring/` are the
acceptance corpus — they must port to the real engine with their behavior
unchanged. Stumble numbers refer to `bench/results/authoring-2026-07-16.md`.

- [x] **Pure render core + pattern contract**
    - Effort: L
    - What: `render(t, mapping, params, seed) → frame` as a pure function, with the ADR-005 pattern base class, normalized world coordinates, persistent frame buffer, and per-frame exception containment.
    - Why: Every other story in this series and every later phase sits on it; purity is what makes golden frames, deterministic scrubbing, and the fleet twin possible (§8, T-1).
    - Dependencies: v0.1.x §12 items 1–2
    - Status: Completed (2026-07-27)
    - Notes: `src/pewpew/{pattern,kit,render,mapping,features}.py`; supersedes `bench/authoring/surface.py`. All five patterns ported to `src/pewpew/patterns/` and proven **bit-identical** (`np.array_equal`, not RMS-tolerant) against the prototype over the study's own 120 frames at seed 42 — `tests/test_port_equivalence.py`. Purity lands at the *sequence* level, not the frame level: ADR-005 patterns are deliberately stateful, so `render_sequence(factory, mapping, params, seed, frames, fps)` is the pure function §8 means, and `Renderer.advance_to(t)`/`.step(dt)` is the live form the paced clock will drive. Timestamps accumulate `t += 1.0/fps` to match `FakeClock` bit-for-bit without importing it (engine must not depend on the harness). `src/harness/` untouched. Also landed: the `time()` module-global hack is gone (frame-scoped `ContextVar`), and a `params` key naming an undeclared `Param` now raises rather than creating a dead knob.

- [x] **Idiom-kit additions mandated by the §12 item-2 verdict**
    - Effort: M
    - What: Add `fade(dt, tau)`, `bins(x, n)`, `sample2d(field, x, y)`, and `hash01(x, salt)` to the standard idiom kit alongside the ADR-005 built-ins (`time()`, `wave()`, `triangle()`, `square()`).
    - Why: The authoring-surface GO was *conditional* on these four — they shield the stumbles the study measured (threshold/dtype edges, frame-rate-dependent decay, per-pixel hashing).
    - Dependencies: Pure render core
    - Status: Completed (2026-07-27)
    - Notes: In `src/pewpew/kit.py`, each a bit-exact substitute for the study expression it replaces, with `tests/test_kit.py` asserting that against the inlined original. Shipped as `hash01(x, seed, salt)` — **seed and salt stay two arguments, deliberately**: the study's `12.9898*x64 + self.seed + salt` associates left-to-right, and a pre-summed salt diverges by 1 ulp on 46 of the study's 120 frames. That is stumble #6's own failure mode one step upstream, so the signature reproduces the study by construction rather than by luck. `fade` is dt-based per Q-5. Adopted at every call site except fire's `lift`, which is `exp(-dt*rise)`, not `exp(-dt/tau)`.

- [x] **Authoring docs for the three measured friction points**
    - Effort: S
    - What: Document the internal-field idiom, that `np.where` evaluates both branches (so guards must be safe, not lazy), and where RNG belongs so patterns stay seed-reproducible.
    - Why: 13 of the study's 17 stumbles were expertise-shielded — an author without NumPy fluency hits them. Docs are the cheapest mitigation the study identified.
    - Dependencies: Idiom-kit additions
    - Status: Completed (2026-07-27)
    - Notes: `docs/authoring.md`. Covers the mandated three (#12/#15, #5, #14) plus the three the study's own "Reading of the evidence" clusters with them: private per-pixel state (#17), dt-decay (#2), and threshold/dtype edges (#6, #9). Every claim cites its `# STUMBLE-N` anchor in `bench/authoring/*.py`, and every example was executed against the real engine rather than written from the docstrings.

- [x] **Decide and implement private per-pixel state buffers (stumble #17)**
    - Effort: M
    - What: Decide whether patterns may declare private per-pixel arrays alongside the sanctioned `self.pixels`, and implement the outcome (including lifecycle across hot reload).
    - Why: The study left this open; fire and any particle pattern need per-pixel state beyond the output buffer, so leaving it undecided blocks a faithful port.
    - Dependencies: Pure render core
    - Status: Completed (2026-07-27)
    - Notes: **Decided yes**, recorded as `## Amendment (2026-07-27)` in ADR-005 with architecture §3 following it. A `setup(n, x, y, z, index)` hook hands the pattern its coordinates once per binding; `self.buffer(name, shape)` declared there is engine-managed (zeroed on rebind, reallocated on mapping change, read-only inside `render`). **Coords-at-setup is the actual unlock** — #17's bind was that `before_render` never sees coordinates. Precedent converged across three lineages: ISF's manifest-declared host-allocated `PERSISTENT` buffers [S218], Shadertoy's previous-state/next-state buffers [S219], and Pixelblaze's persistent arrays [S680] — the last of which pays for them with an *impure render*, the trade we explicitly reject. Registry keys on name+spec, never array identity, because authors rebind (fire does). Two follow-ons this leaves open, both for the hot-reload story: `setup()` failures are deliberately *not* contained (they propagate out of `Renderer.__init__`, so the reload supervisor must keep the last-good binding itself), and scalar per-pattern state (`self.phase`, `self.head`) is not engine-tracked, so reload must decide whether it carries. Also worth a later pass: comet's sparkle still uses the study's time-salted workaround rather than a private buffer, since "behavior unchanged" was the port's acceptance bar — so the corpus does not yet exercise the feature #17 motivated (`docs/authoring.md` §2 demonstrates it instead). Unblocks "Port the upgraded fire to Python" in `unscheduled.md`.

- [x] **Typed params (§5) + param-liveness check in the L1 harness**
    - Effort: M
    - What: Typed `Param` declarations per §5/ADR-006, plus a harness check that wiggles each declared param across its range and asserts the frame sequence actually changes.
    - Why: The sdf3d `spin` parameter was a mathematical no-op and *nothing* caught it — not the authoring surface, not golden frames, because other motion masked it.
    - Dependencies: Pure render core
    - Status: Completed (2026-08-22)
    - Notes: `Param` now validates its own declaration (`lo < hi`, default in range), learns its `name`/`owner` via `__set_name__`, and derives `step`/`decimals`; `declared_params(cls)` reads declarations back off the class and `ParamSet` holds them alongside current values (`src/pewpew/pattern.py`, exported from `pewpew`). Governing record is `## Amendment (2026-08-22)` in ADR-006 — status stays *Proposed*, since Phase 1 lands only the declaration half and the canonical tree (paths, partial-merge, presets, `save`, mDNS) is Phase 3. The Phase-1 object is deliberately a **`ParamSet`, not a tree**: no paths, no nesting, and it must not pre-spend the vocabulary the tree will need. **Range decision: refuse, not clamp** — a clamp renders one value while every surface displays another, which is the dead-knob failure one layer up; float noise at an endpoint snaps (a slider stepping `lo + i*step` can land an ulp past `hi`), anything further out is refused. Refusals split into `reason` (network-safe) and `hint` (names the source file), because the preview server is unauthenticated by design and a refusal must not serve the layout of the disk. **The correction that mattered most**: the first plan resolved params per frame in `advance_to`, justified as preventing a tear between `before_render` and `render` (plasma reads `speed` in one, `scale` in the other). Wrong — `PacedLoop.run` drains `call_soon` at the top of the tick, *before* `advance_to`, so the tear is already impossible; and ADR-006's real per-frame seat must evaluate LFOs *at t*, which needs `t` and the feature frame, neither of which `apply(pattern)` has. Building it would have been the wrong signature for the right reason. Values resolve at bind and **the frame path is untouched**. **Second correction, a live crash path**: `call_soon` propagates a closure's exception out of `run()` (`PacedLoop.call_soon`), so a raising `set_param` reached from the websocket would let a browser stop the aura with one out-of-range slider — verified, `run()` dies with the ValueError. Hence `ParamSet.check()`: non-raising, and the single source of every refusal wording so a socket reply and `set`'s exception can never diverge. The check is `tests/test_param_liveness.py` — nine cases, one per (pattern, knob), self-extending as patterns gain knobs, endpoints rather than a nudge so the declared range is under test too. Acceptance measured both ways: with the xfail removed `sdf3d.spin` fails at **rms 2.65e-08** (not 0 — `angle` still accumulates into cos/sin, it just cannot move a y-axis-invariant SDF), and a freshly-added unread `Param` on geq fails at exactly 0.0. Bar is `LIVENESS_RMS = 1e-3` in `harness/goldens.py`, now shared with `test_golden_frames.py::test_seed_changes_output`, which had the same literal inline. **sdf3d stays frozen** — `test_port_equivalence.py` holds it bit-identical to the study prototype, so fixing the axis would break the evidence chain to repair the very bug that proves the check works; `xfail(strict=True)` means the exemption fails as XPASS if `spin` ever comes alive. Also landed: `Renderer.params` is the set (identity stable across `rebind`, since v0.2.3 holds a reference to it), `Renderer.set_param`, CLI validation moved *ahead* of `Renderer(...)` so a knob typo exits with one clean line while a bad mapping or a raising `setup` still gives a full traceback (binding in `Renderer` is deliberately loud — a blanket `except ValueError` would have quietened it), and one canonical `STUDY_CASES` table in `pewpew.patterns` replacing the (class, mapping) triple three test files each re-derived by hand. Semantic change worth knowing: a `Param` declaration now beats an `__init__` assignment to the same name — the prototype's isinstance guard let `__init__` win — no corpus pattern does it, so bit-exactness holds. **Rejected with numbers**: a descriptor `Param` is the idiomatic 2026 answer and would type `self.speed` as `float`, but measured 4.15 ns plain / 7.4 ns for the current shape / 25–35 ns data descriptor, and the repo runs no mypy, pyright, CI or lint — zero benefit today; revisit when a type checker lands. **Two things v0.2.3 should not rediscover**: `SinkDriver` is *not* reusable for param coalescing (its newest-wins mailbox is one slot, so a `scale` set would discard a pending `speed` set — param coalescing is last-write-wins *per key*), and no rate limiting is needed (a drag fires 60–120 events/s against a 60 Hz drain, ~2 closures per tick); `describe()` is the hello payload, a list so display order survives transport. Left open: a live set only reaches a pattern that reads the knob per frame, so one precomputing from a knob in `setup` would ignore it — that wants a live-set liveness check when a pattern makes it real. This **arms** the second of ADR-010's three GC-retest triggers; the retest is a measurement, due once hot reload lands too.

- [x] **Paced render clock, deadline-corrected (ADR-010)**
    - Effort: M
    - What: One paced clock measuring elapsed, sleeping the remainder, and correcting accumulated error; per-sink newest-wins backpressure bounded at ~2 frames in flight.
    - Why: ADR-010's core mechanism; the single clock is also where modulated params and audio features resolve exactly once per frame.
    - Dependencies: Pure render core
    - Status: Completed (2026-08-20)
    - Notes: `src/pewpew/pace.py` — `PacedLoop` is the bench `deadline` pacer ported exactly (absolute schedule seeded once, skip-ahead with the no-`+1` rule and its rationale comment carried over), plus the spin variant as a `spin_margin` option with `measure_spin_margin()` for the host probe; the engine never auto-probes. The open timestamp question got decided and recorded as `## Amendment (2026-08-20)` in ADR-010: **engine time is nominal schedule time, never measured wall time** — `t += 1/fps` per tick by repeated addition, one further period per skipped slot — so a live run is bit-identical to `render_sequence` at the same slot (`tests/test_pace.py::test_engine_time_matches_render_sequence_bitwise`, `np.array_equal`). Working the skip arithmetic through fixed two wrong intuitions worth keeping: a 2.5-period stall drops exactly *one* slot (the next frame renders immediately, late in the last past slot, rather than idling), and a sub-2-period stall drops *zero* — both are what the no-`+1` rule buys. Backpressure ships as `SinkDriver` (per-sink worker + 1-slot mailbox = Fadecandy's 2-in-flight bound); `PacedLoop` itself takes plain `on_frame(t, frame)` callables handed one shared read-only copy per tick, so the Sink protocol stays owned by the sink story, which wraps its `send` in a `SinkDriver`. Seams left deliberately: `call_soon(fn)` is the loop-thread mutation point hot reload will use, and a callback exception (including an uncaught bind failure) propagates out of `run()` — the reload supervisor owns catching it. Features already resolve once per frame inside `advance_to`; the param tree will hook the same place (typed-params story). GC posture: one frame copy + one tuple per tick, no growing containers — the ADR-010 GC retest obligation (re-bench once sinks + param tree + hot reload exist) stands unchanged.

Leaf-module re-import as §8 asks: each load execs a **fresh module object under a stable `sys.modules` key** (`pewpew_user.<stem>`), never `importlib.reload`, which re-execs into the same object so a renamed class leaves both names behind and, for a gallery file, would rebind `pewpew.patterns.comet.Comet` under `STUDY_CASES`. `swap` has a **strong exception guarantee**: the candidate binds against the inherited param values *before* anything on the renderer changes, so a raising `setup` propagates (bind stays loud, `render.py`) with the old pattern untouched — that settles open point (1). Open point (2) settled by user decision: plain scalar state (`self.head`, `self.phase`) is kept when the new instance has the same name at the same exact type after its own `__init__` (bool/int/float/str only; author-managed arrays start fresh — ADR-005's answer is `self.buffer`), and a name declared as a `Param` on either class is never treated as a scalar, so a knob demoted to a constant takes the author's new constant. Inheritance is a lifecycle hook, not an after-the-fact copy: `Inheritance(old)` (`pattern.py`) is handed to `_bind`, applies `__init__` scalars and the RNG state *before* `setup` (so what `setup` assigns is the new code's own), and each `self.buffer(...)` declaration takes over the old array when name and full `BufferSpec` match (`pixels` included), so a view `setup` derives from a buffer refers to the kept data. Buffers are **copied**, one O(N) per reload: a candidate whose `setup` scribbles on a buffer and then raises has touched nothing the old pattern owns, which is what keeps the strong guarantee honest. A shape or dtype change gets the fresh zeroed buffer. Numbers are one inheritance family (`self.phase = 0` that became a float is kept). Params follow ADR-006 §"Reload policy": kept when they still fit, else reset to the *new default*; the `ParamSet` keeps its identity (the preview's `_LoopControls` holds it) and now stores one `(declarations, values, name)` tuple swapped in a single attribute store, because `describe()` iterating one dict and indexing the other across a redeclare would `KeyError` on a sink worker. #### A real rig: stock WLED boards over Wi-Fi

Shared context (added 2026-10-19). The target rig for pewpew's first real
deployment.

- **Rig.** A laptop renders and sends DDP through a private router (for
  example a GL.iNet Beryl 7, GL-MT3600BE) to
  3 ESP32-S3 DevKitC-1 boards running stock WLED v16.0.1, each behind a
  74AHCT125 level shifter. The fixtures: up to 60 RGBW pixel
  bars (1 m, 64 px, SK6812-type, 24 V, 4 bytes/px) and possibly 12 RGB tubes
  (1.5 m, 36 px, UCS1903, 3 bytes/px). Proposed layout (2026-10-19, not
  yet confirmed): 20 bars per board, 5 per output, on the S3's 4 RMT
  outputs. Open hardware questions (connector pin map,
  RGBW channel order, tube data rate, measured watts per bar) are tracked
  outside this repo.
- **Arithmetic.** 60 × 64 = 3,840 bar pixels, 1,280 per board. One 5-bar
  output takes 320 × 40 µs = 12.8 ms, so the LED wire caps near 76 fps. At
  40 fps RGB each board receives about 154 KB/s. Render cost is not a
  concern: the Phase-0 NumPy kernels took 0.03–0.08 ms per frame at 3,000 px
  (`bench/results/throughput-2026-07-15-mac-m5pro.json`).
- **WLED facts, read from the v16.0.1 source.**
    - DDP pixel format is per packet: 4 bytes when data-type bits 3–5 are
      `011`, else 3; `channelOffset` counts bytes (`wled00/e131.cpp:54-57`).
    - RGB data on an RGBW output gets W from the output's auto-white mode,
      streamed data included (`wled00/bus_manager.cpp:275`; `autoWhiteCalc`
      at `:102-125`). "Accurate" moves the shared part of R, G and B into W.
    - A new streamed frame is shown only when more than 15 ms have passed
      since the last one (`wled00/udp.cpp:477`): about 66 fps at most.
    - Per-board limits: 16,384 px per board and 2,048 per output
      (`wled00/const.h` at the research pin `14709dd`); the S3 has 4 RMT and
      8 parallel outputs.
    - After the realtime timeout (2,500 ms default) a board returns to its own
      state, so its boot preset is the fallback look.
- **Wi-Fi is the main risk.** No measured report was found of stock WLED on
  an ESP32-S3 at this pixel count. Bandwidth is small next to the S3's
  30 Mbit/s UDP receive (Espressif Wi-Fi performance guide); airtime
  contention in a crowded 2.4/5 GHz band is the threat. A WLED developer puts
  live-mode stutter down to the Wi-Fi signal
  ([wled/WLED#5596](https://github.com/wled/WLED/issues/5596)). Stock WLED
  has no Ethernet on the S3
  ([wled/WLED#5478](https://github.com/wled/WLED/issues/5478)).
- **Trust.** The control page and event inputs are unauthenticated by
  design (architecture §5 trust model), which holds only because the router
  is private. Bind to the private router's interface, never to a shared
  network.
- **Hardware tiers (CLAUDE.md T-7).** Before deployment the boards are bench
  hardware (tier 1): flashing and config writes go `--dry-run` first and are
  audit-logged. Once deployed they are tier 2: agents only
  read, and health polling is read-only.

            - Contain is centred: the long axis spans 0–1 and shorter axes are centred (`RoomMap.span`; (1.0, 0.761, 0.0) for the example). ADR-007's 3D y-up convention conflicts with a floor plan, so the amendment records plan orientation (x right, y up the page) as the 2D subset.
            - Boards are declared in the room file as IPv4 literals; a hostname is refused, because re-resolving on a map save blocked the loop for 5 s per unanswering `.local` name. Unchanged boards keep their resolved addresses across a reload. Changed 2026-11-04: an mDNS name (`pewpew-1.local`) is allowed again, looked up by the board monitor off the loop (ADR-004 amendment; "Aura health and restart safety"). Wire order is board, then output, then chain. "Overlapping ranges" became "two board names for one host:port", since ranges are derived and cannot overlap.
            - `--room` streams to the boards (tier 1, audited); `--no-ddp` simulates only. `--room` is refused with `--map`, `--ddp` or `--ansi`, so the ANSI half of "Normalize preview layouts per axis" stays open. A reload that changes the board set writes a `ddp-relayout` audit record first, and a frame rendered for the old layout is dropped.
            - `Renderer.rebind` re-zeroes buffers, reseeds the RNG and is not exception-safe, so a failed rebind rebinds the last good map; if that fails too, the crossfader renders the error frame instead of ending the run.
            - xLights caps a WLED ESP32 port at 3,600 channels [S1279], below WLED's 2,048 px; the check uses WLED's limit, and 320 px per output is under both.
